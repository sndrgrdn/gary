# Defensive mechanisms in Gary

This audit asks whether Gary guards more than a single-user Mac needs. Sander runs his own agent-written plugins, plugins already run with his full user rights, and `host.exec` runs anything. So a guard earns its place only when it stops a shell-level failure or an honest mistake. A shell-level failure means the bar goes away, the Dock or menu bar stays hidden, Gary hangs, or data is lost. A guard that only stops hostile plugins earns little here.

Sander is the only user, and short breakage while he changes things is fine. So compatibility code counts as removable unless it protects the Mac's state. Compatibility code means old names, old formats, support for older macOS versions, and alternate input forms that nothing uses.

The audit covers `Sources/` (the `gary`, `GaryCore`, `GarySocket` and `GaryPrivate` targets) and the CLI at `main` 7f1c77e. Line numbers refer to that commit.

Evidence labels:

- **Measured** means a log line or test shows it.
- **Inferred** means the code was read and traced.
- **Guess** means neither.

The log evidence comes from `~/Library/Logs/gary.log`, which covers about 23 hours and 571 launches of Gary. Git history rarely records incidents. The history holds 298 commits over two days, and most guards arrived with the feature they protect. Commits that fixed a measured crash are cited where they exist.

## Verdict

Gary is not broadly over-defended. Most of its guards protect a real shell failure, such as a crash loop, a hidden Dock, or a runaway script. These guards are small. Gary also carries little compatibility code. About 110 lines of `Sources/` could go, which is 0.7% of the 15,216 lines (guess, ±30). The real cost is friction, not code. A handful of rules make agents fail in ways the log shows. These rules are the `uses` gate, the path confinement rules, all-or-nothing `shell.json`, and the install prompt.

Three gaps matter more than any cut:

- `host.exec` has no deadline.
- A restart request skips the supervisor's restart budget.
- The script time limit will break when plugins share one JavaScript VM.

| `uses` gate, clamping, lenient `shell.json`, arbitrary caps | about 0 net      | about 10           | 2                   |
| **Total removed**                                           | **about 110**    | **about 70**       | **9**               |
| Gap fixes added                                             | about 30         | about 30           | 0                   |

So the net change is about 80 lines of `Sources/`. Code size is not where Gary pays for its defenses. Agents pay in the rules they must learn and the errors they hit.

## Top five changes by value

1. **Make the time-limit watchdog VM-wide before you share the VM.** Without that change, the shared-VM work introduces a use-after-free crash on the first timeout after a plugin unloads. The fix is about 10 lines.
2. **Install every capability regardless of `uses`.** This one-line change removes the `host.exec is not a function` class of errors from agent work. `uses` stays as the declaration for permissions and types.
3. **Give `host.exec` a deadline and kill its child when the plugin stops.** This is the only measured way for honest plugin code to hang a part of Gary for good. The fix is about 25 lines.
4. **Drop path confinement and symlink refusal for plugin files.** This removes about 33 lines, 3 tests, and 4 rules from the guide. A path rule of this family is the most common failure in the log.
5. **Parse `shell.json` per entry.** A typo then costs one widget, not the whole bar on the next start.

Next in line come removing the install prompt, deleting the compatibility code (the `offset` alias, the pre-27.2 window levels, and the unused package forms), moving the registry invariants into tests, and counting restart requests in the supervisor budget.

## Method

- Every `throw`, `guard`, limit, timeout, and budget in `Sources/` was read, along with the CLI in `PluginCommand.swift`, `Cli.swift` and `Doctor.swift`.
- `git log -S` gave the commit that introduced each guard. Only 4dd8f90, dbfe7cf and cb07165 tie a guard to a crash or a system-state risk.
- The log was grepped for failures, rejections, disables, supervisor exits and restores.
- Compatibility code was found by grepping `Sources/` for aliases, fallbacks, version checks and older names, and `git log` for commits that kept a format or name.
- `examples/`, `Resources/plugins/` and `~/Developer/gary-plugins` were grepped to check whether anything still uses an alias.
- The earlier audit in `tmp/audit/audit.md` was used for the `exec` and file-descriptor findings, which were measured there.
- No code was run and no file other than this one changed.
